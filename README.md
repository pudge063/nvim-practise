# vimlab

(repo/directory name is still `vimquest` — renamed the product/UI, not
the folder — see the tree under "Структура репозитория" below)

Браузерная игра для обучения vim: красивый терминал (реальные базовые
команды shell'а) со встроенным hand-rolled эмулятором vim, и панель
заданий рядом — от простых движений курсора до сортировки строк и
`:s`/`:%s`.

Никаких фреймворков — чистые HTML/CSS/JS, без сборки (см.
[docs/adr/0001](docs/adr/0001-no-frameworks.md)).

Под терминалом — карточка с рекламой
[gl.pivlab.dev/rnd/nvim-config](https://gl.pivlab.dev/rnd/nvim-config)
(того самого конфига, которым вдохновлён этот терминал) и
quickstart-командой с кнопкой копирования — в духе `uv`/`poetry`.

## Быстрый старт

```bash
docker compose up --build
```

Открыть: **http://localhost** (порт 80, см.
[docs/adr/0005](docs/adr/0005-local-run-docker-nginx.md)).

Без Docker — тоже работает, но `<script type="module">` требует
настоящего HTTP, не `file://`:

```bash
python3 -m http.server 8080
# затем http://localhost:8080
```

Окно терминала — компактное, примерно по размеру дефолтного окна
macOS Terminal.app, а не во весь экран.

## Что внутри терминала

Реальный (хоть и маленький) shell поверх файловой системы в памяти
(см. [docs/adr/0002](docs/adr/0002-virtual-filesystem.md)):

```
ls, ll, cd, pwd, mkdir, touch, cat, echo, head, tail, wc, grep,
cp, mv, rm, clear, help, vim/vi <файл>, whoami, hostname, date,
uname, uptime, history, w, ps, top, du, df, man, reboot, shutdown,
env, printenv, export, unset, hostnamectl, lscpu, ip
```

`top` — не разовый снимок, а **живой** режим на весь экран, прямо как
настоящий: значения (CPU/память/PID'ы) сами обновляются каждые 1.5с,
выход — клавишей **`q`**, и, как в настоящем терминале (alternate screen
buffer), вывод `top` при выходе исчезает бесследно — экран возвращается
ровно к тому, что было в терминале до запуска `top`. `ps` печатает такой
же снимок процессов, только разовый. `history` — настоящая история
именно ваших команд в этой сессии. `head`/`tail`/`wc`/`grep`/`cp`/`mv`
работают по-настоящему с виртуальной ФС (ADR-0002), не только для
красоты.

`ls`/`ll` понимают флаги `-l` (длинный формат), `-a`/`-A` (показать `.`
и `..`) в любой комбинации (`-la`, `-al`, `-lA`...). `rm` принимает
несколько файлов за раз, флаг `-f` (не ошибаться на несуществующих
файлах) и раскрывает glob `*`/`./*`/`<каталог>/*` в список файлов этого
каталога — своего полноценного шелл-глоббинга тут нет, только этот один,
самый частый шаблон. Любая команда понимает `--help`/`-h` — печатает
свою `man`-строку, как в настоящем Linux.

Переменные окружения: `env`/`printenv [NAME]` показывают их,
`export NAME=value` задаёт, `unset NAME` убирает. `$NAME` и `${NAME}`
разворачиваются в значение переменной **в любом месте любой команды** —
в аргументах, в цели редиректа (`echo hi > $HOME/out.txt`), даже в самом
имени команды; неопределённая переменная разворачивается в пустую
строку, как в настоящем шелле. Строка вида `ИМЯ=значение` сама по себе
(без `export`) тоже задаёт переменную — по умолчанию заведены `HOME`,
`USER`, `SHELL`, `TERM`, `LANG`, `HOSTNAME`, `PATH`, а `PWD`/`OLDPWD`
всегда живые — берутся прямо из текущего/предыдущего каталога, а не
из отдельного сохранённого значения, которое можно было бы забыть
обновить.

`hostnamectl` (`-l` — больше полей: hardware vendor/model, firmware) и
`lscpu` — как настоящие, только с придуманными значениями. `ip a`
выводит `lo` и `eth0` с адресом — это не реальный IP пользователя:
получить его без стороннего сетевого запроса браузер не может, а
дёргать внешний сервис ради этого не хотелось (лишняя сетевая
зависимость плюс отправка IP пользователя третьей стороне без явного
на то согласия).

`shutdown` (по умолчанию через 5с; `-h now` — сразу; `shutdown N` —
через N секунд) печатает лог выключения, затем терминал гаснет —
чёрный экран с кнопкой питания прямо в окне терминала (не на всю
страницу, как пасхалка `rm -rf /`). Нажатие кнопки — лог загрузки и
терминал снова доступен. В отличие от `reboot` (перезагружает саму
страницу, ADR-0002), `shutdown` страницу не трогает — файловая система
переживает выключение/включение, как настоящий диск.

`reboot` тоже теперь не мгновенный — сперва свой лог перезагрузки, затем
настоящая перезагрузка страницы (и вот тут, в отличие от `shutdown`, всё
честно сбрасывается — ADR-0002), а на свежей странице перед тем, как
терминал станет доступен, ещё и лог загрузки — весь цикл выглядит
непрерывным «ушёл вниз — поднялся», а не логом с обрывом на пустой
терминал.

`cd` понимает `~`, `-` (предыдущий каталог) и `--`. `echo текст > файл`
перезаписывает файл, `>>` дописывает в конец (работает и для вывода
других команд, не только `echo`). `vim`/`vi` — синонимы; `<файл>`
открывает его во встроенном vim-эмуляторе, а без аргумента (или с `.`,
или с путём к каталогу) открывает лёгкий файловый браузер: `j`/`k`
двигают выделение, `Enter` заходит в каталог или открывает файл, `-`
поднимается на уровень выше, `q`/`Esc` выходит в шелл. Это отдельный
режим в `terminal.js`, не часть движка `vim.js` — специально, чтобы не
раздувать зафиксированный в ADR-0003 объём самого vim-эмулятора.
`reboot` перезагружает страницу. Весь вывод самого терминала — на
английском, как в настоящем шелле (задания и подсказки в панели справа
— на русском, это разные уровни интерфейса).

**Tab** дополняет команды, имена файлов и — если курсор стоит сразу
после незаконченного `$ИМЯ` или `${ИМЯ` — переменные окружения (`echo
$U` → `echo $USER`, `${HOM` → `${HOME}`, закрывающая скобка достраивается
сама), как в настоящем терминале. Не переключает фокус на другой элемент
страницы.

Файловая система не сохраняется между перезагрузками страницы — это
осознанное решение, не баг (см. ADR-0002).

Пасхалки:
- `rm -rf /` (и вариации — `/*`, `*` из корня, любой порядок `-r`/`-f`)
  — секунда фейковых ошибок ядра с тряской и красным свечением окна,
  затем экран ослепляет белой вспышкой (звук `flashbang.mp3`), проявляется
  картинка на весь экран, и в момент, когда она полностью проявилась —
  ещё звук удара (`pum-impacto.mp3`); через несколько секунд страница
  сама перезагружается.
- `sudo` (с любыми аргументами) — то же самое, сразу со вспышки, без
  фазы ошибок.

Восстановиться можно только перезагрузкой страницы — это часть шутки,
не баг.

## Что умеет встроенный vim

Это не обёртка над настоящим vim и не сторонняя JS-библиотека — весь
движок в `js/vim.js` написан с нуля и **сознательно** покрывает только
подмножество команд, нужное для заданий. Полный список того, что
реализовано (и явно не реализовано — макросы, метки, `.`-повтор и т.д.)
— в [docs/adr/0003](docs/adr/0003-vim-emulator-scope.md).

Коротко: режимы Normal/Insert/Visual/Visual-Line/Command-line;
движения `h j k l w b e 0 ^ $ gg G f{char}` (с числовыми
повторителями); операторы `d y c` + `iw`/`aw`; `x r p P o O i a I A`;
`u`/`Ctrl-r`; поиск `/` `n` `N`; command-line `:w :q :wq :{N} :sort
:'<,'>sort :s/../../  :%s/../../g`. `cw` отдельно копирует поведение
настоящего vim (ведёт себя как `ce`, не съедая пробел после слова) —
эта деталь всплыла при добавлении заданий и была специально исправлена
в движке, не обойдена в формулировке задания.

## Режимы: свободно / обучение / задания

Страница открывается в **свободном режиме** — после короткого (~1.6с)
лога загрузки терминал доступен, никто ничего не проверяет и не
подсказывает, печатайте что хотите. Тот же лог загрузки, что и после
`shutdown`/`reboot` — терминал на странице ведёт себя как настоящая
машина, которая при каждом обращении к ней действительно включается, а
не просто материализуется в уже готовом виде.
Вкладки **«📘 Обучение» / «🎯 Задания»** над панелью справа всегда
слегка светятся (даже до того, как вы выбрали хоть один режим) — это
приглашение попробовать, не требование.

**Обучение** (открывается по клику, не само) — 9 шагов подряд
(открыть vim, движение `hjkl`, `0`/`$`, Insert mode, `dd`, `u`, `:wq`),
каждый со своей подсказкой прямо в терминале — подсказка не пропадает
сама, пока шаг не выполнен, и шаг засчитывается автоматически, как
только действие сделано (см.
[docs/adr/0007](docs/adr/0007-tutorial-mode.md)).

**Задания** — свободный выбор из полного набора (см. ниже); выполнили
одно — через полторы секунды само открывается следующее по списку.

Переключение между режимами — в любую сторону, без потери прогресса ни
в одном из них.

## Задания

42 задания в 5 категориях (Движение, Слова и выделение, Поиск,
Сортировка и команды, Редактирование) — плитками в панели справа, клик
переключает между ними. Выполненное задание — зелёная плитка с
галочкой. Каждое задание само подставляет нужный файл и стартовую
позицию курсора при открытии.

За выполнение — от 1 до 3 звёзд (по соотношению фактических нажатий к
справочному "у профи выходит за N" — это всегда только награда, никогда
не требование: задание засчитывается по результату, см.
[docs/adr/0004](docs/adr/0004-task-validation.md)). При выполнении —
всплеск звёзд по экрану и подсветка статуса.

Подсказка доступна двумя способами:
- кнопка с лампочкой в панели — открывает её по требованию в любой
  момент (что нужно сделать и почему, не точная последовательность
  клавиш — способов сделать одно и то же в vim обычно несколько, и
  проверка задания принимает любой из них);
- всплывающая подсказка **внутри самого терминала** — появляется сама,
  если нажатий стало заметно больше справочного числа, а задание всё
  ещё не выполнено (и повторяется, если застряли надолго).

**Свободный режим** (кнопка над списком заданий) открывает vim без
привязки к какому-либо заданию — никаких проверок и подсказок, можно
делать что угодно.

## Разработка / тестирование

`js/vim.js` — чистый JS без DOM, поэтому проверяется напрямую через
встроенный тест-раннер Node (без зависимостей — та же логика, что и
ADR-0001, только для dev-тулинга, а не для самого приложения):

```bash
node --test tests/vim.spec.mjs
```

25 тестов: все мотивы (`h l j k w b e 0 ^ $ gg G f`) включая счётчик
перед `f`/`r`/`gg` (регрессия — см. CHANGELOG), операторы
(`d y c` × `iw`/`aw`/`dd`/`f`), `cw`'s special-case (не то же самое, что
`dw`), `x r p P o O i a A`, visual mode (charwise и linewise), поиск
(`/ n`), `:sort`/`'<,'>sort`, `:s`/`:%s`, undo/redo (+ `redoCount`),
`:w`/`:q`-колбэки.

DOM-слой (`terminal.js`, `tasks.js`) автотестами пока не покрыт —
проверялся вручную в браузере. Ручная проверка: `docker compose up
--build`, открыть http://localhost, попробовать пару заданий из
каждой категории.
